# Host-native Test Scope interpretation pilot

## Pre-registered scope (2026-10-08)

The provider-backed CLI study encountered execution-policy rejection of input
reads and analysis commands. Six completed responses are unavailable environment
observations, not performance/error samples. Its controller was stopped, owned
processes terminated and temporary input directories removed. No policy was
disabled or relaxed. [The original CLI design](AGENT_STUDY.md) remains a separate
uncompleted thirty-session study.

The owner's independent-agent authorization also permits a smaller host-native
pilot using this session's supported delegation surface. Before collecting its
answers, register twelve fresh `fork_turns="none"` default-role agents: two Test
Scope task families, two conditions, three repeats per family/condition. Each
agent inherits the same host model/settings; authoritative model snapshot and
token usage are not exposed by this surface. No different model, endpoint or
authentication is selected. Run trials sequentially in a pseudorandom order
with seed 20261008. A separate fresh grader sees shuffled opaque answer IDs and
reference facts, with conditions/timing/commands withheld.

The known family uses the forty-three Git-frozen Test Evidence files and asks for
the five direct-import suites. The unfamiliar family uses the separately authored
billing/helper/fixture/type-check input from the CLI registration and asks for
the two direct/transitive suites. This checks interpretation of a familiar
package and one authored naming example; it is not a repository-generalization
study. Conventional agents inspect bounded source and metadata. Tool agents use
the refined Test Scope CLI and may clarify source evidence. Both conditions have
at most six evidence commands, including at most two discovery calls, and the
same structured answer fields and explicit prohibition on running tests.

Agents own only their individual answer/journal files and preserve all other
work. Instrumented shell calls retain complete arguments and returned tool
objects; final structured answers and prompts are retained. The host does not
export full underlying session transcripts or usage. Therefore this pilot does
not satisfy those observability requirements of the full CLI protocol and cannot
establish token savings or complete end-to-end agent productivity. Journals are
agent-authored, with input/source consistency and deterministic fact checks by
the primary agent; they are not authenticated server telemetry.

Grade all five/two required paths, exclusion of support inputs, static coverage
limits and absence of unsupported execution/pass claims. Independently compare
returned paths with frozen references. Report grading disagreements, unavailable
trials and scope violations. Wall time includes host scheduling and reasoning;
command-output bytes/calls come from instrumented journals. Setup and grading
are separate costs; three samples cannot establish statistical significance.
No rejected trial is silently replaced. The pilot leaves native contracts,
registry/release state, root gates and the original measurements unchanged.

Retain local registration, prompts, journals, answers, grades and hashes under
`.cache/agent-study/host-pilot-*/`. Remove owned fixture directories after checking
input/source consistency. Portable results must distinguish this pilot from the
blocked CLI study. TASK/VALIDATION own current acceptance and commit status.
