# Complete repair workflow pilot

The owner selected this opt-in development study on 2026-10-09. This protocol is frozen before participant execution. It does not change AIT, tool implementations, native scripts or the earlier studies.

## Case and scope

Replay a real Markdown-Editor defect at source commit `f373f6f3bf77c3f1ce5d6ddb11adfa94c1ee4096`, immediately before historical fix `29cc3899eb76e348a3ff9d72a9c1fd7f146ab429`. The missing internal-image placeholder interpolated alt text into HTML. Mermaid error output escaped only `<`, losing literal entity text. This is a historical repair replay, not a newly discovered defect in current HEAD. Participants receive the buggy source and behavior requirements, never the historical patch, solution or repository history.

Complete the module-level workflow: locate both rendering boundaries, change source, add a native regression test, execute all supplied native tests, review the actual patch and assess source-bound evidence. Allowed edits are the two renderer files, optional `src/preview/htmlEscape.js`, and new `test/previewSafety.test.js`. Existing tests, package metadata, lockfile, unrelated source and study support are protected. Ordinary image/link/table/fence behavior, successful SVG and lazy loading must remain intact. This is not browser, application build, accessibility or full security acceptance.

## Registered design

- Six fresh sequential Codex CLI sessions: conventional and tool workflows, three repetitions each, randomized with seed `20261010` before collection.
- Request `gpt-6.1-sol`, reasoning `xhigh`, CLI `0.161.0`, Ubuntu WSL Node `24.19.0`. Requested settings are not authenticated backend execution facts.
- Use the supported `workspace-write` sandbox in an owned temporary fixture, with approval policy `never`. Preserve execpolicy; no sandbox/rule bypass, additional writable directories, credentials, network commands, Git operations, installations or delegation by participants.
- Same source, requirements, final-answer schema, dependency setup, producer, permitted source edits and 900-second deadline in both arms. Failed/unavailable attempts remain in the denominator and are not replaced.
- Conventional participants use ordinary reads/searches, edits, native tests and inspect the producer's patch/counts/source/process receipts. Tool participants additionally use Code Slice, Test Scope, Patch Guard and Test Evidence at their respective stages. Each tool must be attempted at least once; unsuccessful uptake is recorded, never treated as use. The treatment is this instructed four-tool workflow, not any single tool or optimal optional tool selection.
- A common caller-owned collector snapshots source, records the actual native process result, emits a projected Node reporter capture and a complete source diff, and constructs a declared source/environment request. The reporter is shared measurement instrumentation; conventional participants do not call the evidence analyzer. The collector does not repair source or decide the verdict.
- Existing frozen tests run before collection. Independently authored acceptance tests exercise the actual image renderer callback and Mermaid hydrator through VM-linked modules, using real Markdown-It and controlled React/image/math/Mermaid/DOM boundaries. TypeScript only transpiles JSX for this fixture. Baseline must fail acceptance; the historical source repair must pass both native and acceptance checks. Participants do not receive acceptance tests or the historical source repair.
- Locked dependencies are prepared once with `npm ci --ignore-scripts --omit=dev --no-audit --no-fund`. Their setup time is reported separately from participant costs; a shared dependency directory is read-only to participants. No lifecycle scripts run. Source repositories must stay unchanged.

Pre-collection execution amendment: the first preparation attempt completed zero repair participants and was retained. In this sandbox, default Node test-worker IPC produced file-only events, and `spawnSync` with captured pipes returned `EPERM` and an empty capture even alongside status zero. Test Evidence correctly withheld it. Direct two-case controls reproduced the boundary. Use explicit `--test-isolation=none` for both arms and descriptor-backed capture in the common producer, preserving sandbox and network restrictions. Assert the exact six-case baseline and eleven-case acceptance counts before starting participants, not merely process success. Earlier failed preparation bytes remain unchanged.

## Primary decision and measurements

Independent post-participant verification checks every changed path and protected byte, reruns all native tests and the frozen acceptance tests, and hashes the exact submitted source before/after execution. Acceptance requires a nonempty permitted patch, an authored regression file, both native and acceptance checks passing without fail/skip/todo/cancelled, stable source, and an explicit final `pass` backed by a current successful receipt. A self-reported pass or analysis exit zero alone is insufficient. Independently correct repairs and adequate end-to-end answers are separate fields.

Record actual provider-emitted command and file-change events, call counts, UTF-8 emitted command-output bytes, reported input/cached/output tokens, elapsed participant time, independent verification time, source/diff/artifact hashes, actual process outcomes, tool uptake and final answers. Preserve exact prompts, JSONL, stderr and producer outputs in an explicit ignored local evidence directory. File-change events are permitted only in this pilot; they remain forbidden in the older read-only studies. Report command failures and policy rejection separately from repair failure. Review command inventory and final diffs manually before drawing conclusions.

Keep conditions and repetition labels when reporting. Use descriptive counts and per-arm medians, no significance or causal/productivity/billing/generalization claims from one selected historical defect and three repetitions. Shared setup, experiment controller, independent verification and participant costs have separate boundaries. No blind prose grader is needed: frozen runtime acceptance, path/byte invariants and manual evidence review own this pilot's criteria. Record practical value even when the tool workflow is slower or equivalent.

## Execution and failure handling

`python scripts/evaluate-repair-workflow.py --run --node <task-local-linux-node> --codex-js <official-cli-js>` explicitly runs the study. A bounded authorized write/native-test preflight must pass before participant execution. Preserve failed preflights; do not weaken controls. The runner freezes protocol, harness, support, acceptance tests, source and tool identities before trials and stores all retained evidence under `.cache/repair-workflow/`. Remove only the owned temporary fixtures after source and tool identity readback. Keep the authenticated task-local runtime for later owner-authorized work. No automatic commit, push, publication, KB writeback, cloud configuration or monitoring is included.
